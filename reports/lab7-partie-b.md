# Lab 7 — partie B : évaluation et promotion

La politique v1 a été commitée avant les évaluations. L'archive de A ne contenait ni `.git` ni `artifacts/` : le commit d'import reconstruit ne prétend pas reproduire l'historique original. Le modèle de référence a été reconstruit avec le pipeline et ses octets correspondent exactement au SHA-256 publié pour model-001 ; il a été adopté localement sous ce nom avec la version publiée. Les manifests sont conservés dans `reports/evidence/lab7-b/`. Deux configurations sur un budget de trois ont été utilisées.

Sur les mêmes 4 358 lignes de validation, la MAE de la moyenne du train vaut 154,231793 ; celle de model-001 86,846857 ; celle du candidat peu profond 106,594449 vélos/heure. Ce dernier bat la baseline naïve mais échoue à la marge contre model-001 : décision `rejected`, code 4. Le candidat identique à model-001 est `accept`, code 0, par équivalence et sans amélioration. Les décisions comprennent les empreintes, résultats et raisons. Le SHA-256 des couples ordonnés instant/cnt de validation est enregistré. Aucune métrique du test n'a été calculée.

Les tests des trois cas limites ont été exécutés sur trois mutations délibérées temporaires du gate, puis sur le code restauré : voir `reports/evidence/lab7-b/mutations-red.log` et `gate-green.log`. Les mutations ont supprimé l'obligation du contrôle opérationnel, accepté une entrée malformée et rendu stricte l'égalité à la marge ; ce sont des défauts injectés pour le test, pas des décisions réelles.

La preuve locale du refus est dans `reports/evidence/lab7-b/review-clean-clone.json` : clone propre de ce dépôt, réinstallation des artefacts locaux vérifiés, refus réel de promotion, comparaison de `promote status`, empreintes du modèle accepté et servi, réponse health et prédiction du service. Le processus de service est testé par TestClient en mémoire, pas sur un déploiement distant. Pour transmettre à A : configuration `configs/candidates/rf-shallow.json`, manifest et décision `reports/decisions/12d65c86c763c029.json` ; le fichier modèle est dans les artefacts locaux ignorés par Git. Le run_id dépend du code et de l'identité ; ne pas remplacer la décision par une décision d'un autre run.

La CI configurée installe le lock, vérifie lint/format et exécute les tests, mais aucun résultat CI distant n'est affirmé ici. Elle ne prouve pas une promotion ni la disponibilité réelle du service en production. Le gate ne peut pas savoir si les données reflètent le futur, si les labels sont corrects dans le monde réel, ni garantir latence, équité ou dérive. La limite de taille n'est pas une mesure de latence. Les modèles joblib doivent être de confiance. Les décisions sont des preuves locales, pas une autorité cryptographique ni un contrôle d'accès.

Environnement : l'installation `uv sync --locked` a échoué faute d'accès réseau et de tous les paquets en cache ; les exécutions locales ont utilisé un environnement Python 3.12 existant, avec scikit-learn 1.9.1, et ne constituent pas la preuve d'une installation verrouillée complète.
